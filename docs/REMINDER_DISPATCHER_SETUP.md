# Acadly Web Push sender and Supabase scheduling setup

This runbook configures the VAPID sender implemented in
`supabase/functions/reminder-dispatcher/index.ts`. The function queues due
reminders, sends Web Push notifications, retries transient failures with
exponential backoff, and disables subscriptions whose endpoints return 404/410.

## 1. Generate VAPID keys locally

From `frontend/` (or any folder with Node/npm), run:

```powershell
npx --yes web-push@3.6.7 generate-vapid-keys --json
```

Copy the public and private keys from the output. Never commit the private key
or paste it into frontend variables. Set the subject to a contact URI you own,
for example `mailto:admin@your-domain.example`.

## 2. Configure Edge Function secrets

Open Supabase Dashboard → Project Settings → Edge Functions → Secrets for
project `pcvkmsbtlszsuvuuvpnq` and add:

| Name | Value |
|---|---|
| `WEB_PUSH_VAPID_PUBLIC_KEY` | VAPID public key from step 1 |
| `WEB_PUSH_VAPID_PRIVATE_KEY` | VAPID private key from step 1 |
| `WEB_PUSH_VAPID_SUBJECT` | `mailto:` contact URI |
| `ACADLY_CRON_SECRET` | Random secret generated by the setup script below |

The function uses the platform-injected `SUPABASE_SECRET_KEYS` (preferred) or
legacy `SUPABASE_SERVICE_ROLE_KEY` to access the database. Do not create a
`VITE_*` variable for any server-side secret.

Generate and set the cron secret with the existing PowerShell script:

```powershell
.\scripts\setup-reminder-dispatcher.ps1
```

The script uses the Supabase CLI to set `ACADLY_CRON_SECRET` and prints it once.
Keep that value private; the same value must be stored in Vault in step 3.
If the CLI is not linked, run `supabase login` and `supabase link --project-ref
pcvkmsbtlszsuvuuvpnq` first.

## 3. Configure the frontend public key

Set this build-time variable in Cloudflare Pages (or your frontend host):

```text
VITE_WEB_PUSH_VAPID_PUBLIC_KEY=<VAPID_PUBLIC_KEY>
```

This is a public key and is safe in the browser. Trigger a new frontend build
after setting it. Do not put the VAPID private key in frontend configuration.

## 4. Store the cron invocation values in Supabase Vault

In Supabase Dashboard → SQL Editor, run the following after replacing the
placeholder with the exact cron secret printed by the setup script:

```sql
select vault.create_secret(
  'https://pcvkmsbtlszsuvuuvpnq.supabase.co',
  'acadly_project_url'
);

select vault.create_secret(
  '<PASTE_THE_GENERATED_CRON_SECRET>',
  'acadly_cron_secret'
);
```

If a secret with either name already exists, update it through the Vault
Dashboard rather than creating duplicate names. Never save literal secrets in
Git, issue comments, or shared SQL snippets.

## 5. Enable and schedule pg_cron + pg_net

The migration `20261110120000_enable_acadly_reminder_cron.sql` enables the
extensions. After it is applied and Vault has both secrets, run:

```sql
select cron.unschedule(jobid)
from cron.job
where jobname = 'acadly-reminder-dispatcher';

select cron.schedule(
  'acadly-reminder-dispatcher',
  '* * * * *',
  $$
    select net.http_post(
      url := (select decrypted_secret from vault.decrypted_secrets where name = 'acadly_project_url')
        || '/functions/v1/reminder-dispatcher',
      headers := jsonb_build_object(
        'Content-Type', 'application/json',
        'x-acadly-cron-secret', (select decrypted_secret from vault.decrypted_secrets where name = 'acadly_cron_secret')
      ),
      body := '{}'::jsonb,
      timeout_milliseconds := 55000
    );
  $$
);
```

The Edge Function already has `verify_jwt = false` and independently checks
`x-acadly-cron-secret`. Do not remove that check or expose the cron secret to
the browser.

Verify the schedule and recent HTTP responses:

```sql
select jobid, jobname, schedule, active
from cron.job
where jobname = 'acadly-reminder-dispatcher';

select id, status_code, error_msg, created
from net._http_response
order by created desc
limit 20;

select status, count(*)
from public.push_delivery_jobs
group by status
order by status;
```

## 6. Deploy and verify

After adding the Edge Function secrets, deploy the updated
`reminder-dispatcher` from this branch (or merge the PR and deploy from main).
Then rebuild the frontend with the public VAPID key.

In the app, sign in, open Settings → Study reminders, and enable push on the
current device. Create a test reminder due in the next minute. Confirm that the
browser displays the notification and that the corresponding
`push_delivery_jobs` row reaches `sent`.

## Delivery behavior

- Due reminders are queued once per active subscription.
- Successful sends are marked `sent`.
- 404/410 endpoints are marked expired and their subscriptions are disabled.
- Other failures retry with exponential backoff up to 10 attempts, then become
  terminal `failed` rows.
- The cron job runs every minute. Browser/OS delivery can still be affected by
  device notification settings and push-provider availability.
